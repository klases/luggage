# Host activation and limits

Explicit artifact loading means directing the host to read this package's SKILL.md and relevant references from an authorized path. For an evaluation, record the hashes of the frozen skill and any supplied agent instructions, along with which files were read. Native activation means the host discovered and selected its supported skill or agent definition. Record the activation path and available tools separately. Use machine-produced identity receipts rather than manually retyping long hashes. A controller should verify the receipt against frozen bytes and retain actual file-read evidence; a model's claimed loading path or hash alone is not proof that it read the artifact. A receipt transcription error is a reporting defect, not automatic evidence that every code finding is false.

| Host | Discovery and activation | Agent and permission limits |
|---|---|---|
| Claude Code | The Klases plugin is intended to expose `/klases:code-reviewer` after discovery. This package's native activation has not been exercised. | The plugin agent Markdown uses Claude Code's read/search tools. Pass the absolute skill directory or read-only artifact path when dispatching, since prompt-relative paths may need resolution by the caller. Host permissions and execution containment remain separate from prompt instructions. |
| Codex | Explicitly load the artifact by path. Native `$code-reviewer` requires discovery in a supported skills location and has not been tested for this package. | Claude agent Markdown can be read as instructions. Native agent definitions use Codex's own format. Separate threads inherit host permissions, so use a constrained parent or a sequential pass. |
| Hermes | Explicitly load by path. Named activation requires discovery in a configured or trusted skill location and has not been tested for this package. | A fresh task can receive bounded instructions if delegation and tool restrictions are available. Verify actual tools and isolation before relying on them. Shared working directories and fallback environments may expose writable state. |

Use host permissions and OS controls for enforcement. Treat aliases, built-in review commands, native agent execution and explicit file reads as distinct entry points. When an independent reviewer or safe execution is unavailable, report the reduced coverage and continue with the permitted read-only pass.
